## 加载与取景

四套导出均为 **Spine 4.0.17**，已用项目安装的官方 **4.0.31** 运行时解析和实际 WebGL 绘制。加载同名 JSON 与 atlas，选择动画 **`loop`** 并启用循环，即可播放整幅分层画面。使用直通 alpha，`premultipliedAlpha: false`。

取景框以 JSON 自带的 `skeleton.x / y / width / height` 为准，均为 16:9：

| 素材 | x | y | width | height |
| --- | ---: | ---: | ---: | ---: |
| image_1 | -1600 | -900 | 3200 | 1800 |
| image_2 | -1200 | -675 | 2400 | 1350 |
| image_3 | -2400 | -1350 | 4800 | 2700 |
| image_4 | -1200 | -675 | 2400 | 1350 |

坐标保留原骨骼单位，因此四套的数字尺寸不同；按以上边界等比适配后，对应参考图的同一画幅。不要让播放器按全部离屏网格自动扩大取景，否则前景与天空在设计框外的延伸会把主体缩小。Spine Web Player 可把上述四个字段直接作为 `viewport`，并将四侧 padding 设为 0；自绘相机使用相应宽高、中心 `(0, 0)`。不需要原网页的 `layout.json` 或运行时额外摆放数据。

所有原动画也以 `layer_序号_层名/原动画名` 保留，共 **51 条**，可以单独调试入场、眨眼和其他循环。整幅壁纸通常只播放新增的 `loop`；单独播放某层原动画时，其他层保持默认姿态。

完整壁纸整理时未改映射；F 当前恢复 image_2 无 Role / 十四页 / 四十秒循环，原始与派生数据保持。独立 nahida_swing、十七套用户角色按需使用，不将秋千烘回背景；其他三套完整壁纸未整体接入。G 仅换 background.png 静态图，见 PAGE_ASSETS.md。

## 位置、大小与动态处理

原播放器使用 `SkeletonJson.scale = 0.01`，却没有补回 Unity Canvas 的 100 referencePixelsPerUnit；骨架相对于独立图片缩小了 100 倍。整理时恢复参考像素换算，保留场景中的页面平移、缩放、父子位置和前后绘制顺序，将每层的摆放写入合成骨骼。

天空、建筑、云、地面等独立图片转为标准 Spine region 附件，保留图片大小、颜色及镜像关系。没有重绘纹理，**53 张 PNG 的 SHA-256 均与原导出一致**；原图集的旋转角度、裁切尺寸、偏移和网格 UV 也保留。

各图所有动态层恰好有同一基础比例，使用共同取景单位表达该比例，避免把统一缩放塞入父骨后破坏 `noScale`、`onlyTranslation` 等继承模式。原骨骼、IK / transform / path 约束、网格权重、原动画关键帧与变形数据保留，只为合成重命名引用并修正加权顶点的骨骼索引。

不同层按原时长独立循环。合成 `loop` 采用 30 FPS 时间基的最小公倍周期，重复较短的原循环，并同步平移贝塞尔控制点的时间；没有拉伸动画。也处理了延迟首关键帧、周期末尾保持和周期边界跳变，避免短循环停住或提前缓动。最长 50 秒是美梦场景原有泡泡层的周期。

参考图是静帧。预览选择接近参考的动画时刻，表情、秋千角度、飘浮位置和花草摆幅仍会继续变化；没有为了固定截图而改写动作。
